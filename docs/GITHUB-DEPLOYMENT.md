# inklade/SONAR 자동 수집·배포

대상 저장소: https://github.com/inklade/SONAR
사이트 주소: https://inklade.github.io/SONAR/

## 저장소에서 한 번만 설정

1. Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 선택합니다.
2. Settings → Secrets and variables → Actions → New repository secret에서 이름을 **YOUTUBE_API_KEY**로 등록합니다. 키 값은 소스나 채팅에 넣지 않습니다.
3. Actions → SONAR · collect, verify & deploy → Run workflow에서 `collect`를 꺼 두면 저장된 실제 데이터로 배포만 합니다. 켜면 수집 후 배포합니다.

코드 연결은 GitHub 앱의 인증을 사용합니다. 과거 채팅의 GitHub 자격 증명을 사용하지 않습니다. GitHub 연결만으로 Secret 값을 등록하거나 Pages 관리 설정을 바꾸지는 못하므로 위 설정은 저장소에서 직접 해야 합니다.

## API 호출을 줄인 구조

브라우저의 유형·그룹·멤버·선호 선택은 localStorage와 저장된 JSON만 사용합니다. 방문자 수나 사용자가 고른 그룹 수 때문에 YouTube API가 호출되지는 않습니다. 수집 대상은 `collectionEnabled` 설정으로 별도 관리합니다. 현재 디렉터리는 19개지만 우선 수집 그룹은 9개이고, 공통 외부 채널 2개를 포함해 활성 소스는 11개입니다.

| 작업 | 주기/방식 |
| --- | --- |
| 최근 업로드 목록 | 6시간마다 채널별 50개 1페이지. 기존 실제 영상은 유지 |
| 영상 메타데이터 | ID 중복 제거 후 50개씩 videos.list 묶음 호출 |
| 새 라이브 발견 | 공식 채널의 live 검색만 실행. 예약 방송 검색은 제거 |
| 알려진 라이브 확인 | 20분 간격 videos.list. 후보가 없으면 API 호출 0회 |
| 채널 식별 정보 | 같은 채널의 검증된 ID·업로드 재생목록 ID 재사용 |
| 변경 없는 라이브 확인 | 불필요한 타임스탬프 변경과 사이트 재배포 생략 |

새 라이브는 전체 수집 때 발견하므로 즉시 발견을 보장하지 않습니다. 현재 9개 공식 소스는 약 6시간 간격이며, 소스가 20개를 넘으면 순환 조회로 발견 간격이 길어질 수 있습니다. 이미 발견한 라이브의 상태는 20분 간격으로 갱신합니다. GitHub 예약 작업 자체도 지연될 수 있습니다.

## 한도와 현재 예상량

2026-11-05 확인한 [Google 공식 문서](https://developers.google.com/youtube/data/determine_quota_cost)는 검색을 별도 버킷 **하루 100회**, 기타 API를 합산 **하루 10,000단위**로 안내합니다. 프로젝트에 실제 적용된 한도는 Google Cloud Console의 Quotas에서 확인합니다. 과거의 ‘검색 1회=100포인트’ 설명과 혼동하지 않습니다.

- 기존 방식: 9개 공식 소스 × live/upcoming 2회 × 하루 4회 = 검색 72회/일.
- 변경 방식: live만 검색하여 검색 약 36회/일.
- 최근 영상 90개 기준 일반 조회 예상: 약 124단위/일. 알려진 라이브 후보 한 묶음을 매번 조회한다고 가정한 추정이며, 처음 채널을 확인하거나 신규 영상·재시도가 늘면 추가됩니다. 라이브 후보가 없으면 더 적습니다.

### 자동 제한

- 검색: 1회 실행 최대 20회, 최근 24시간 최대 80회.
- 기타 조회: 1회 실행 최대 600회, 최근 24시간 최대 8,000회.
- 실패·재시도도 요청 전에 사용량을 기록합니다. 최근 24시간 기준으로 계산해 실제 일일 한도보다 여유를 둡니다.
- 검색 대상이 많으면 저장한 커서로 순환합니다. 특정 소스만 계속 선택하지 않습니다.
- 일반 조회 한도에 도달하면 공개 데이터를 덮어쓰지 않고 종료합니다.
- 사용 이력은 public/data/collection-state.json에 저장합니다. 수집 실패 시에도 이 파일만 따로 커밋해 다음 실행에서 사용량을 잊지 않게 합니다. 키는 저장하지 않습니다.

```console
python -m collectors.quota --estimate
```

제한은 이 수집기가 기록한 요청에 대한 것입니다. 같은 API 프로젝트를 다른 앱이나 별도 수집기가 사용하면 그 사용량까지 알 수는 없습니다. 수집 상태 파일을 지우거나 다른 저장소에서 같은 키를 동시에 사용하면 공통 한도 보호가 되지 않습니다. 여러 키로 한도를 우회하는 구성은 사용하지 않습니다.

## 배포 동작

main 코드가 바뀌면 검사·빌드·Pages 배포를 실행합니다. 정기 수집에서는 실제 공개 영상/라이브 데이터가 바뀐 경우에만 배포합니다. API 예산 장부만 바뀐 경우는 사이트 재배포를 생략합니다. 수집 작업의 커밋 SHA를 빌드가 그대로 사용해 이전 데이터를 배포하지 않습니다. GitHub Actions 기본 토큰의 커밋이 별도 push 워크플로를 다시 실행하지 않는 점도 고려한 구성입니다.

Pages가 아직 설정되지 않으면 배포 단계가 실패할 수 있습니다. 설정 후 같은 Actions 실행을 재실행하거나 main에서 Run workflow를 실행합니다. Secret이 없으면 자동 수집은 명확한 오류를 내고 기존 데이터를 보존합니다. Secret 없이도 collect=false 수동 배포는 가능합니다.
