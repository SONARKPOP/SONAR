# 실제 YouTube API 연결 점검

기존 네 그룹의 실제 API 연결로 영상 20개를 수집했고 현재 화면에 반영했습니다. 추가 다섯 그룹의 연결·수집은 아직 대기 상태입니다. 키는 저장하지 않았으므로 다음 실행 때 숨김 입력이 필요합니다. 채팅으로 API 키를 보내지 마세요.

## 1. 키 준비

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 선택/생성합니다.
2. APIs & Services → Library에서 YouTube Data API v3를 활성화합니다.
3. Credentials → Create credentials → API key를 생성합니다.
4. 해당 키의 API restrictions를 YouTube Data API v3로 제한합니다. 수집은 Python에서 호출하므로 브라우저 referrer 전용 제한은 맞지 않습니다. 프로젝트 운영 환경에 맞는 제한을 적용합니다.

## 2. 소량 연결 점검

프로젝트의 **CONNECT-YOUTUBE.cmd**를 더블클릭합니다. API 키를 물으면 실행 창에 붙여넣고 Enter를 누르세요. 입력한 문자는 화면에 표시되지 않습니다. 키를 파일이나 영구 환경변수에 저장하지 않고 현재 Python 실행에서만 사용합니다. 기존 YOUTUBE_API_KEY 환경변수가 있으면 그 값을 사용합니다.

다른 환경에서는 다음 명령을 사용합니다. 숨김 입력을 위해 대화형 터미널에서 실행해야 합니다.

```sh
python -m collectors.preflight --prompt-key --limit 5
```

- 수집이 켜진 공식 채널의 채널 ID/업로드 재생목록을 해석합니다.
- 채널별 최근 업로드 최대 5개와 해당 영상 상세를 가져옵니다. 현재 기본 설정은 네 공식 채널입니다.
- 이 점검은 비싼 전체 검색이나 live/upcoming 검색, 외부 채널 수집을 하지 않습니다.
- API 호출이 모두 성공한 뒤 새 review/<실행시각>/ 폴더에 결과를 저장합니다.
- public/data와 실제 사이트의 샘플 화면은 교체하지 않습니다.

성공 시 `REPORT.md`, `report.json`, `data/`가 생성됩니다. 실패 시 키/쿼터/채널 관련 안내를 확인하세요. API 연결 점검은 공식 채널 여부를 자동으로 보증하는 절차가 아니므로 해석된 채널 ID와 영상을 원본에서 확인하세요.

## 3. 검수

report.json의 review 항목에서 영상별 URL을 확인합니다.

- 영상이 해당 그룹의 공식 채널에서 올라왔는가?
- 연결된 그룹/멤버가 실제 출연하는가, 설명에서 언급만 됐는가?
- MUSIC/자체 콘텐츠 분류가 맞는가?
- Shorts 표기가 맞는가? 영상 길이만으로 확정하지 않습니다.

오분류는 config/overrides.json에 플랫폼 접두사 없는 YouTube 영상 ID로 수정합니다. 신규 라이브/예약 방송/외부 출연 영상은 이 점검 범위에 포함되지 않으며 전체 수집 때 별도 확인합니다.

## 4. 공개 데이터 전환

검수 후 전체 수집은 README의 환경변수 방식 또는 GitHub Secrets를 사용합니다. `python -m collectors.youtube`를 실행하면 샘플을 실제 수집 결과로 교체합니다. 소량 점검 보고서를 그대로 공개 데이터로 덮어쓰지 마세요.

review 폴더는 Git에 포함하지 않습니다. 보고서에는 키를 저장하지 않지만 공개 전 검수용 메타데이터이므로 ZIP 배포에도 제외합니다. 실패 메시지를 공유할 때 키가 들어간 화면이나 요청 주소를 붙여넣지 마세요.

## 기존 실제 데이터를 유지하면서 9개 그룹 갱신

UPDATE-ACTUAL.cmd를 실행하면 새 검수 수집 결과를 기존 실제 영상에 병합합니다. 공개 화면의 샘플/예시 일정은 이미 제거되어 있습니다. 현재 멤버 분류는 제목만 사용하고, 설명의 단체 멤버 목록은 무시합니다. 자세한 현황은 [PRIORITY_GROUPS.md](PRIORITY_GROUPS.md)를 확인하세요.
